# Как считаются показатели

Все показатели написаны на чистой стандартной библиотеке Python: без numpy, scipy,
shapely и pycocotools. Здесь по шагам описано, что делает код и где он лежит, чтобы
каждое число можно было проверить руками. Что показатели означают и как их включать
в конфигурацию — в [docs/metrics.md](../../../docs/metrics.md).

| Файл              | Что в нём                                                                                        |
|-------------------|--------------------------------------------------------------------------------------------------|
| `../polygon.py`   | выпуклая оболочка, площадь многоугольника, пересечение выпуклых многоугольников                  |
| `../boxes.py`     | рамки `BoundingBox3D` (по осям) и `OrientedBox3D` (ориентированная), их объём, пересечение и IoU |
| `matching.py`     | жадное сопоставление предсказаний с эталоном                                                     |
| `detection.py`    | `object_map`, `object_map_dataset`, протокол классов, AP                                         |
| `layout.py`       | `layout_iou_3d`                                                                                  |
| `physics.py`      | `collision_rate`, `layout_violation_rate`, `layout_penetration`                                  |
| `shape.py`        | `mesh_chamfer`, `mesh_fscore`: чтение сеток, выборка точек, k-d дерево                           |
| `../evaluator.py` | сбор значений по сценам, среднее, медиана, доверительный интервал                                |
| `../config.py`    | `_expand_metrics`: развёртывание `per_class: true` в строки по классам                           |

## Рамки и их пересечение (`boxes.py`, `polygon.py`)

**Рамка по осям** `BoundingBox3D(min_corner, max_corner)`: объём — произведение длин по
трём осям, пересечение — произведение перекрытий `max(0, min(max) − max(min))` по каждой
оси. Так обычно задаётся макет комнаты.

**Ориентированная рамка** `OrientedBox3D(center, size, basis)`. Строки `basis` — оси рамки
в координатах мира. Угол рамки — `center + Σ_k (±size_k / 2) · basis[k]`, всего 8 углов
(`corners`). Нечисловые значения (`NaN`, `inf`) при создании заменяются нулём, отрицательный
размер — нулём (`_finite`). Поэтому вырожденная рамка становится рамкой нулевого объёма,
а не роняет подсчёт.

**Объём пересечения двух ориентированных рамок** (`intersection_volume`):

1. След на полу: берутся координаты XY всех 8 углов каждой рамки (`_footprint`).
2. Выпуклая оболочка следа — алгоритм Эндрю, монотонная цепь (`convex_hull`). Точки
   округляются до 12 знаков, чтобы почти совпадающие углы не давали вырожденных рёбер.
3. Пересечение двух выпуклых многоугольников — отсечение Сазерленда — Ходжмана
   (`convex_intersection_area`): след первой рамки последовательно обрезается каждым
   ребром второй. Точка считается внутри, если векторное произведение ≥ −1e−12.
4. Площадь результата — формула площади Гаусса (`polygon_area`).
5. Перекрытие по высоте: отрезки `[min z, max z]` по углам каждой рамки (`_z_span`),
   длина их пересечения.
6. Объём пересечения = площадь × перекрытие по высоте, но не больше объёма каждой
   из рамок.

Это точный объём для рамок, стоящих вертикально (поворот только вокруг Z) — так устроены
рамки всех методов и эталона. Для наклонённой рамки получится приближение: её след и
высота берутся по описанному параллелепипеду.

**IoU** = пересечение / (объём₁ + объём₂ − пересечение), при нулевом объединении — 0.
Рамка по осям при сравнении с ориентированной переводится в ориентированную
(`as_oriented`).

## Сопоставление (`matching.py`)

`greedy_match(predictions, labels, iou_threshold)`:

1. Предсказания сортируются по убыванию `score`.
2. Каждое предсказание по очереди считает IoU со всеми ещё не занятыми эталонными
   предметами и берёт лучший.
3. Если лучший IoU ≥ порога — пара засчитана, эталонный предмет занят. Иначе предсказание
   ложное.

Каждый эталонный предмет может быть сопоставлен только один раз. В детектировании
сопоставление идёт **внутри одного класса**: функции передаются предсказания и эталон
одного класса. В показателях формы — **без учёта класса**, по всем предметам сцены сразу.

## Детектирование (`detection.py`)

**Протокол классов** (`_ClassProtocol.apply`), если задан `classes` или `class_map`:
сначала класс переименовывается по `class_map` (предметы, которых нет в таблице,
выбрасываются), затем остаются только классы из `classes`. Фильтр применяется к
предсказаниям и эталону одинаково, до сопоставления.

**AP одного класса** (`_ap_from_detections`):

1. Каждое предсказание после сопоставления — пара `(score, попало)`.
2. Пары сортируются по убыванию `score`; накапливаются число попаданий TP и промахов FP.
3. После каждого предсказания: точность = TP / (TP + FP), полнота = TP / число эталонных
   предметов класса.
4. Интерполяция по всем точкам (`_interpolated_ap`): для каждого различного уровня
   полноты r берётся наибольшая точность среди точек с полнотой ≥ r, и
   AP = Σ (r_i − r_{i−1}) · точность(r_i). Это схема PASCAL VOC начиная с 2010 года.
5. Если эталонных предметов класса нет, AP = 0.

**`object_map`** (по сцене): предметы делятся по классам; AP считается для каждого класса,
у которого в сцене есть эталон, и усредняется. Класс, который предсказан, но в эталоне
сцены отсутствует, не учитывается; класс с эталоном, но без предсказаний, даёт AP = 0.
Если в сцене нет эталонных предметов: при протоколе классов — NaN (сцена не войдёт
в среднее), без протокола — 0.

**`object_map_dataset`** (по набору): пары `(score, попало)` каждого класса собираются со
**всех** сцен в один список, число эталонных предметов класса тоже суммируется по всем
сценам. По этим общим спискам считается AP класса, затем среднее по классам, у которых
в наборе есть эталон. Сопоставление при этом по-прежнему идёт внутри сцены. Если эталона
нет нигде — 0.

## Макет (`layout.py`)

`layout_iou_3d` — IoU предсказанного и эталонного макета (`prediction.layout.iou(...)`,
формулы выше). Нет эталонного макета — NaN, нет предсказанного — 0.

## Физическая правдоподобность (`physics.py`)

Эталон не нужен, считается только по предсказанию.

**`collision_rate`**: перебираются все пары предметов сцены (i < j). Пара сталкивается,
если объём пересечения рамок больше `minimum_intersection` (по умолчанию 0). Значение —
доля сталкивающихся пар; если пар нет — 0.

**`layout_violation_rate`**: для каждого предмета с ненулевым объёмом доля объёма вне
макета = 1 − пересечение(предмет, макет) / объём предмета. Предмет нарушает макет, если
эта доля больше `tolerance` (с запасом 1e−9 на погрешность). Значение — доля нарушающих
предметов. Нет макета — NaN; нет предметов — 0.

**`layout_penetration`**: то же, но вместо доли нарушающих предметов — средняя доля объёма
вне макета по всем предметам с ненулевым объёмом.

Предметы нулевого объёма в этих двух показателях пропускаются. Вырожденные рамки
(`NaN` в координатах) становятся рамками нулевого объёма, поэтому сцены с ними
дают заниженные значения — так получилось у DPC@100 на iGibson.

## Форма (`shape.py`)

**Откуда берутся точки** (`load_shape_points`, поле `attributes["shape"]`):

- `.ply` (ASCII и binary little-endian) и `.obj` читаются собственными разборщиками;
  многоугольные грани режутся веером на треугольники (`_fan`);
- `.f32` / `.bin` — сырые float32 little-endian, по три числа на точку;
- `.json`, список `[[x,y,z], ...]` или словарь `{"points": ...}` — точки как есть.

**Выборка точек с поверхности** (`_sample_surface`): площади треугольников (половина длины
векторного произведения) складываются в накопительную сумму; для каждой точки случайное
число в `[0, сумма)` ищется двоичным поиском — так треугольник выбирается с вероятностью,
пропорциональной площади. Точка внутри треугольника — равномерно, через барицентрические
веса `1 − √r₁, √r₁(1 − r₂), √r₁·r₂`. Генератор случайных чисел создаётся заново с одним
и тем же `seed` для каждого предмета, поэтому повторный подсчёт даёт те же точки.
Сетка без граней — точки выбираются из вершин.

**Нормировка пары** (`_normalize_pair`):

- `none` — как есть;
- `canonical` — каждая форма отдельно: центр её рамки по осям в начало, деление на
  диагональ этой рамки;
- `unit` — обе формы: вычитается центр масс точек эталона, деление на диагональ рамки
  эталона.

**Ближайшие соседи** — k-d дерево (`_build_kd`): точки делятся по медиане, ось чередуется
x → y → z. Поиск (`_nearest_sq`) — обход стеком: сначала ближняя ветвь, дальняя
проверяется, только если плоскость разреза ближе текущего лучшего расстояния.

**Чамфер и F-мера одной пары** (`chamfer_and_fscore`), d — квадрат расстояния до
ближайшей точки другого облака:

```
chamfer   = mean(d(pred → gt)) + mean(d(gt → pred))           squared=True
chamfer   = mean(√d(pred → gt)) + mean(√d(gt → pred))         squared=False
точность  = доля точек pred, у которых d ≤ τ²
полнота   = доля точек gt,   у которых d ≤ τ²
F-мера    = 2 · точность · полнота / (точность + полнота)
```

τ — `fscore_threshold`, в единицах облака после нормировки.

**Значение по сцене**: предметы сопоставляются жадно по IoU (без учёта класса, см. выше),
для каждой пары, где у обоих есть форма, считается значение, затем среднее по парам.
Пар нет — NaN, сцена не входит в среднее.

## Сводка по набору (`evaluator.py`)

- Для каждой сцены считаются все показатели по сцене. NaN не записывается и в сводку
  не попадает. Показатели, которым нужен эталон, на сценах без эталона пропускаются.
- **Среднее** — `statistics.fmean`, **медиана** — `statistics.median`.
- **95 % доверительный интервал** (`_bootstrap_ci`): 2000 повторных выборок с возвращением
  того же размера; для каждой — среднее; средние сортируются, границы — значения на
  позициях 2.5 % и 97.5 %. Генератор случайных чисел задаётся `seed` конфигурации, поэтому
  интервал воспроизводится. Для одной сцены интервал равен среднему.
- **Показатели по набору** (`object_map_dataset`) считаются один раз по всем сценам
  с эталоном, интервала у них нет.
- `per_class: true` разворачивается ещё при чтении конфигурации (`config.py`) в отдельные
  показатели `<name>_<класс>` с `classes: [<класс>]`, то есть AP класса считается тем же
  кодом, что и mAP.
