# `environments/` — окружения моделей

Каждой модели нужен свой стек (у DPC — Python 3.7 и старый PyTorch), поэтому модель
работает в отдельном окружении, а ядро только собирает его и запускает в нём раннер.
Как писать спецификацию и пользоваться командами `env` — в
[docs/architecture.md](../../../docs/architecture.md#менеджер-окружений), готовые
спецификации — в [configs/README.md](../../../configs/README.md).

| Файл         | За что отвечает                                                                                                                    |
|--------------|------------------------------------------------------------------------------------------------------------------------------------|
| `spec.py`    | `EnvironmentSpec` и его части (`RepoSpec`, `CheckpointSpec`, `RunnerSpec`), чтение спецификации, отпечаток для маркера             |
| `base.py`    | `EnvironmentManager`: маркер готовности, `is_prepared`, `adopt`; реестр `ENVIRONMENT_MANAGERS`; `EnvHandle` — как запускать раннер |
| `conda.py`   | бэкенд `conda`: основной, для семейства DPC                                                                                        |
| `venv.py`    | бэкенд `venv`: лёгкие модели и локальная разработка                                                                                |
| `steps.py`   | шаги сборки: запуск команды, клон репозитория, загрузка весов с проверкой sha256, локальный кэш весов                              |
| `patches.py` | правки исходников модели при сборке: снять жёсткие версии, вставить строки, `git apply`                                            |
| `plan.py`    | `env prepare --dry-run` и `--verify`: что уже есть, что требует сети, совпадают ли веса                                            |
| `doctor.py`  | `env doctor`: какие бэкенды и GPU есть на машине                                                                                   |
| `submit.py`  | `env submit-script`: скрипт sbatch или bash для кластера                                                                           |

Окружение считается готовым, когда есть маркер `.pano3dbench/markers/<имя>.json` с тем же
отпечатком спецификации и само окружение существует.
