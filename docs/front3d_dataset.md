# Набор 3D-FRONT версии 1

Набор, на котором обучены и оценены методы в [front3d.md](front3d.md). Его собирает генератор
[front3d-pano](https://github.com/HoloPano-dissertation/front3d-pano), а здесь лежит то, что
нужно, чтобы собрать именно этот набор: состав в
[configs/front3d/splits/](../configs/front3d/splits/), параметры и контрольные числа.

## Исходники

- Комнаты `3D-FRONT-SCENE` переработки MIDI-3D, список `valid_room_ids.json`: 10 514 комнат.
- `3D-FRONT.zip` и `3D-FRONT-texture.zip` исходного релиза.

Что и откуда скачать, описано в документации генератора (`docs/data_sources.md`).

## Состав

|-------------------------------------------------|----------------------------------:|------------------------------------:|
| исходный список                                 |                            10 514 |                                     |
| исключено при `freeze` и рендере по архитектуре |                               947 |                                     |
| исключено после финального рендера (`reject`)   |                                22 |                                     |
| **итоговый набор**                              | **9 545 (6 670 / 1 443 / 1 432)** | **38 180 (26 680 / 5 772 / 5 728)** |

Части указаны в порядке train / val / test. Разбиение по домам: все комнаты одной квартиры
лежат в одной части. Обучающих классов 14: класс предмета становится обучающим, если у
него набралось не меньше 100 экземпляров, поэтому на наборе другого размера список
классов будет другим.

## Как собрать этот набор

Шаги — по `docs/pipeline.md` генератора, но шаги 2 (`freeze`) и 7 (`reject`) пропускаются:
состав уже зафиксирован, и `init` берёт его отсюда.

```bash
front3d-pano metadata /data/raw/3D-FRONT.zip /data/3D-FRONT-SCENE \
  /data/source_metadata.json --rooms /data/3D-Front/valid_room_ids.json
front3d-pano init /data/3D-FRONT-SCENE /data/front3d --splits $TBX/configs/front3d/splits
```

Дальше архитектура, рендер с параметрами ниже, `export` и `validate`. Если `reject` всё же
нужен, его надо запускать на копии папки разбиения: команда правит файлы, которые ей
переданы.

## Параметры рендера

| Параметр              | Значение                                                                  |
|-----------------------|---------------------------------------------------------------------------|
| BlenderProc, Blender  | 2.8.0, 4.2.1                                                              |
| разрешение            | 1024×512                                                                  |
| видов на комнату      | 4                                                                         |
| `--samples`           | 96                                                                        |
| `--ambient`           | 4.0                                                                       |
| `--light-temperature` | 2700-5000                                                                 |
| `--min-clearance`     | `min(0.1, 0.04 × высота комнаты)` для каждой комнаты, записывается `init` |
| архитектура           | из исходного релиза (`--architecture-root`)                               |

## Чем набор версии 1 отличается от выгрузки нынешним генератором

Набор версии 1 отрисован до того, как код принял вид отдельного пакета. Логика рендера и
разметки та же: разметка генератора на 30 комнатах (120 видов) совпала с набором версии 1 —
эталон, отношения и COCO до шума округления, сетки предметов побайтно или до 6·10⁻¹¹.
Отличаются только строки:

- метка набора в перечнях и эталоне: `MIDI-3D-FRONT-1K-custom` в версии 1, `front3d-pano` сейчас;
- описание рамки макета `layout_box_semantics` в эталоне и `layout_type` в `state/ground_truth.json`;
- хеши файлов рендерера в `render.json`. Поэтому дорисовать папку версии 1 нынешним кодом
  нельзя, `render` остановится: для нового рендера нужна новая папка.
