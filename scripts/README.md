# Скрипты

Вспомогательные скрипты, которые запускаются **в окружении модели** (`Pano3D`), а не
в окружении комплекса: им нужен код DeepPanoContext, а для iGibson — ещё и `gibson2`.
Запуск — `conda run -n Pano3D python <скрипт> ...`. Ниже `$DPC` — клон DeepPanoContext,
`$TBX` — этот репозиторий.

```text
scripts/
├── dpc/        работа с кодом и выводом DeepPanoContext, для любого набора
├── front3d/    форматы методов и проверка набора 3D-FRONT, см. front3d/README.md
├── igibson/    подготовка данных набора iGibson
└── slurm/      шаблоны задач Slurm: обучение, вывод и подсчёт обоих наборов, см. slurm/README.md
```

Шаблоны `slurm/` запускаются на узле входа кластера и отправляют задачи в очередь:
подробно — в [slurm/README.md](slurm/README.md).

Скрипты `front3d/` запускаются в окружении генератора `front3d-pano`, а не в `Pano3D`,
кроме сцен DPC: подробно — в [front3d/README.md](front3d/README.md).

## `dpc/` — для любого набора

| Скрипт                 | Что делает                                                                                                                     | Когда нужен                                                                                        |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| `dpc_postsetup.py`     | вносит правки в код DeepPanoContext, без которых он не работает вне Colab и на наших данных; повторный запуск ничего не ломает | один раз после развёртывания окружения, до любого вывода или обучения                              |
| `dpc_batch_convert.py` | переводит вывод DPC (`data.pkl` каждой сцены) в JSON `SceneOutput` и пишет перечень `manifest_pred.jsonl`                      | чтобы считать показатели по готовым предсказаниям (`*_rescore.yaml`) и для всей оценки на 3D-FRONT |
| `dpc_loader_probe.py`  | перебирает пакеты загрузчика DPC по конфигурации без модели и останавливается на первом пакете, где пропали предметы           | перед долгим обучением BEN или Scene-GCN на новых данных                                           |

**`dpc_postsetup.py`**

```bash
conda run -n Pano3D python $TBX/scripts/dpc/dpc_postsetup.py $DPC
```

Правки по порядку:

| Правка                                                                                                    | Зачем                                                                                                                                                                 |
|-----------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ленивый импорт ChamferDistance                                                                            | вывод работает без собранного расширения CUDA (для обучения его всё равно нужно собрать)                                                                              |
| пустая сцена                                                                                              | сцена без предметов не роняет вывод                                                                                                                                   |
| сохранение `data.pkl` до трёхмерной визуализации и выгрузка сеток предметов (`DPC_PATCH_EXPORT_OBJ_MESH`) | предсказание сохраняется, даже если визуализация упала; в режиме `--mode test` каноническая сетка каждого предмета пишется в `obj_mesh/<i>.ply` для показателей формы |
| `contour_clip` в списке полей, которые склеиваются списком                                                | обрезанный контур, как и обычный, собирается в пакет списком, а не тензором                                                                                           |
| вырожденные рамки в оценке                                                                                | встроенная оценка DPC считает IoU вырожденной (NaN или вывернутой) рамки нулём, а не падает                                                                           |
| `num_workers = 0` в конфигурациях iGibson                                                                 | данные читаются в главном процессе, без отдельных процессов загрузки                                                                                                  |
| `no_grad` при проверке                                                                                    | проверка MGN не строит граф градиентов и не упирается в память GPU                                                                                                    |
| оценка отношений только при сопоставлении с эталоном (`DPC_PATCH_REL_EVAL_NEEDS_GT`)                      | показатели отношений требуют предметов, сопоставленных с эталоном; на 3D-FRONT в сценах есть отношения, и без правки вывод падал с `KeyError: 'gt'`                   |
| обмен тензорами через файловую систему (`DPC_PATCH_FS_SHARING`, `main.py`)                                | загрузчик с несколькими процессами не упирается в предел открытых файлов (`Too many open files`) при обучении BEN и Scene-GCN                                         |

**`dpc_loader_probe.py`**

```bash
cd $DPC && PYTHONPATH=$DPC conda run -n Pano3D python $TBX/scripts/dpc/dpc_loader_probe.py \
    <конфигурация DPC> [--mode train] [--steps 300]
```

Код возврата 1 и имена сцен, если в пакете нет предметов у предсказания или эталона.

**`dpc_batch_convert.py`**

```bash
conda run -n Pano3D python $TBX/scripts/dpc/dpc_batch_convert.py \
    <manifest.jsonl> <папка для JSON> --repo $DPC --pred-root out/pano3d \
    [--obj-mesh-sibling obj_mesh]
```

| Аргумент             | Смысл                                                                                                                                                             |
|----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `manifest`           | перечень сцен с эталоном (для iGibson его строит `dpc_build_igibson_manifest.py`, для 3D-FRONT — генератор)                                                       |
| `out_dir`            | куда писать `<sample_id>.json` и `manifest_pred.jsonl`                                                                                                            |
| `--repo`             | клон DeepPanoContext (по умолчанию — текущая папка)                                                                                                               |
| `--pred-root`        | папка вывода конфигурации: `out/pano3d` для DPC, `out/pano3d_im3d`, `out/pano3d_total3d` и т. д. У каждой конфигурации своя, иначе предсказания методов смешаются |
| `--obj-mesh-sibling` | имя папки с сетками рядом с `data.pkl` (обычно `obj_mesh`); путь к сетке записывается в `attributes["shape"]` для показателей формы                               |

Перевод использует тот же код, что и раннер (`runners/dpc_runner.py`), поэтому оба пути
дают одинаковые числа.

## `igibson/` — набор iGibson

| Скрипт                          | Что делает                                                                                       | Когда нужен                           |
|---------------------------------|--------------------------------------------------------------------------------------------------|---------------------------------------|
| `dpc_build_igibson_manifest.py` | строит эталон iGibson в формате комплекса и перечень сцен тем же конвертером, что и предсказания | один раз перед подсчётом iGibson      |
| `mgn_make_gt.py`                | считает цели MGN для предметов iGibson: точки поверхности и их плотность                         | только для обучения головы MGN с нуля |

**`dpc_build_igibson_manifest.py`**

```bash
conda run -n Pano3D python $TBX/scripts/igibson/dpc_build_igibson_manifest.py \
    $DPC $DPC/data/igibson_bench $DPC/data/igibson/test.json
```

Аргументы: клон DeepPanoContext, папка результата (`gt/` и `manifest.jsonl`),
необязательный список сцен (например, тестовая часть). Переменная `IGIBSON_OBJ_ROOT`
добавляет каждому предмету его замкнутую сетку `<корень>/<model_path>/mesh_watertight.ply`
для показателей формы.

После любой правки `runners/scene_payload.py` или `dpc_runner.convert_data_pkl` эталон нужно
построить заново: стороны сравнения строятся одним кодом.

**`mgn_make_gt.py`**

```bash
conda run -n Pano3D python $TBX/scripts/igibson/mgn_make_gt.py $DPC --processes 8
```

| Аргумент      | Смысл                                              |
|---------------|----------------------------------------------------|
| `repo`        | клон DeepPanoContext                               |
| `--data-dir`  | папка предметов (по умолчанию `data/igibson_obj`)  |
| `--n-points`  | точек на предмет (10000)                           |
| `--k`         | сосед, по которому считается плотность (30)        |
| `--processes` | число процессов (8)                                |
| `--overwrite` | пересчитать уже готовые                            |
| `--limit`     | обработать только первые N предметов, для проверки |

Для 3D-FRONT такие же цели делает `front3d/adapters/export_mgn_points.py`.

Подробно, в каком порядке всё запускать: [docs/igibson.md](../docs/igibson.md),
[docs/front3d.md](../docs/front3d.md).
